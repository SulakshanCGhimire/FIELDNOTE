# ADR 0001: Minimum SDK 24

## Context
FIELDNOTE needs to work for field teams, so supporting older Android phones matters. At the same time, choosing a very old minimum SDK can make development more complicated and may require additional compatibility handling.

The project wizard shows that minSdk 24 provides approximately 99.2% device coverage for the target distribution.

## Options

### Option 1: Use a very old minimum SDK
- **Advantage:** More older Android devices can run FIELDNOTE.
- **Disadvantage:** We may need more compatibility handling and may have fewer modern Android APIs available directly.

### Option 2: Use a more recent minimum SDK
- **Advantage:** Development can be simpler because more modern Android APIs are available.
- **Disadvantage:** Some older phones used by field teams may no longer be supported.

## Decision
We will use minSdk 24 for FIELDNOTE.

This gives us approximately 99.2% coverage while still allowing us to support older devices that field teams may use. The choice is a trade-off between broad device compatibility and the convenience of relying on newer Android platform capabilities.

## Consequences
- FIELDNOTE can target the stated 99.2% device coverage, but we must still test behavior across Android versions and handle differences in permissions, APIs, and system behavior where necessary.
- Devices running Android versions below API 24 will not be supported.
